# Diagramas C4

El modelo C4 describe el sistema con distintos niveles de acercamiento. Cada nivel responde una pregunta diferente. Se incluyen los tres niveles útiles para esta actividad; el nivel 4 (código) se omite porque los [fragmentos C#](casos-uso-puertos-adaptadores.md) ya lo describen con más precisión que un diagrama.

| Nivel | Pregunta que responde | Diagrama |
| :--- | :--- | :--- |
| 1 · Contexto | ¿Quién usa LogiTracker y con qué sistemas se conecta? | [Ir](#nivel-1-contexto) |
| 2 · Contenedores | ¿Qué aplicaciones y almacenes de datos forman el sistema? | [Ir](#nivel-2-contenedores) |
| 3 · Componentes | ¿Qué módulos hay dentro de la API y cómo se organiza Entregas? | [Ir](#nivel-3-componentes) |

> En C4, un **contenedor** es una unidad que se ejecuta o almacena datos (una aplicación web, una API, una base de datos). No significa un contenedor Docker. La tecnología concreta de cada contenedor se decide en la Actividad 4.

## Nivel 1: Contexto

## Nivel 2: Contenedores

Muestra las aplicaciones que forman LogiTracker. Hay **un solo contenedor de backend**, coherente con la decisión de monolito modular del [ADR-001](../adr/ADR-001-estructura-monolito-modular.md).

```mermaid
graph TD
    %% Actores
    Cliente[👤 Cliente]
    Personal[👤 Operador, Almacén y Soporte]
    Repartidor[👤 Repartidor]
    Canales[🛒 Canales de Venta]

    subgraph Limite [LogiTracker]
        Portal[🌐 Portal de Seguimiento <br> Aplicación web para clientes]
        WebOps[🖥️ Aplicación de Operación <br> Aplicación web interna]
        AppMovil[📱 App del Repartidor <br> Aplicación móvil con modo sin conexión]
        API[⚙️ API LogiTracker <br> Monolito modular: reglas de negocio <br> y procesos en segundo plano]
        BD[(🗄️ Base de Datos Operativa <br> Un esquema por módulo)]
    end

    %% Sistemas externos
    Externos[🏢 Pagos, Geolocalización, <br> Notificaciones, ERP/CRM]

    %% Relaciones
    Cliente -->|Consulta estado del pedido| Portal
    Personal -->|Gestiona pedidos y asigna entregas| WebOps
    Repartidor -->|Recibe asignaciones y reporta estado| AppMovil
    Portal -->|Consultas de seguimiento - HTTPS/JSON| API
    WebOps -->|Comandos y consultas - HTTPS/JSON| API
    AppMovil -->|Eventos de entrega, sincroniza al reconectar| API
    Canales -->|Pedidos - HTTPS/JSON| API
    API -->|Lee y escribe| BD
    API -->|A través de adaptadores| Externos
```

| Contenedor | Responsabilidad |
| :--- | :--- |
| **Portal de Seguimiento** | Muestra al cliente el último estado conocido de su pedido. No contiene reglas de negocio. |
| **Aplicación de Operación** | Permite registrar pedidos, asignar repartidores y gestionar incidencias. Aquí el operador inicia el flujo de asignación. |
| **App del Repartidor** | Muestra las entregas asignadas y registra eventos, incluso sin conexión (RF-11). |
| **API LogiTracker** | Contiene todos los módulos de negocio y los procesos en segundo plano (por ejemplo, el envío de hechos pendientes). Es el único contenedor con reglas de negocio. |
| **Base de Datos Operativa** | Guarda los datos de cada módulo en un esquema propio. Ningún módulo lee el esquema de otro. |

## Nivel 3: Componentes

### 3.1 Módulos dentro de la API

```mermaid
graph TD
    %% Entrada
    Controladores[🌐 Controladores HTTP <br> Traducen HTTP a casos de uso]

    subgraph API [API LogiTracker]
        Pedidos[📦 Módulo Pedidos]
        Inventario[📊 Módulo Inventario]
        Entregas[🚚 Módulo Entregas]
        Ruteo[🗺️ Módulo Ruteo]
        Incidencias[⚠️ Módulo Incidencias]
        Auditoria[📋 Auditoría]
        Despachador[📤 Despachador de hechos <br> Proceso en segundo plano]
    end

    BD[(🗄️ Base de Datos Operativa)]
    Notif[📲 Servicio de Notificaciones]

    %% Relaciones
    Controladores --> Pedidos
    Controladores --> Entregas
    Controladores --> Incidencias
    Pedidos -->|¿Stock reservable?| Inventario
    Pedidos -->|C-01 Pedido listo para logística| Entregas
    Entregas -.->|C-05 Estimar ruta| Ruteo
    Entregas -->|Guarda hechos pendientes| BD
    Despachador -->|Lee hechos pendientes| BD
    Despachador -->|C-03 Repartidor asignado| Pedidos
    Despachador -->|C-03 Repartidor asignado| Auditoria
    Despachador -->|C-04 Aviso| Notif
```

### 3.2 Componentes del módulo Entregas (flujo de asignación)

```mermaid
graph TD
    %% Entrada
    Controller[🌐 DeliveriesController <br> Adaptador de entrada]

    subgraph Entregas [Módulo Entregas]
        subgraph App [⚙️ Aplicación]
            UseCase[AssignCourierUseCase <br> Coordina la asignación]
            Ports[Puertos <br> IDeliveryRepository <br> ICourierAvailability <br> IDeliveryEventPublisher <br> IClock]
        end

        subgraph Dom [💎 Dominio]
            Delivery[Delivery <br> Protege INV-01 a INV-10]
            Availability[CourierAvailability <br> Regla de ruta saturada]
        end

        subgraph Infra [🔌 Infraestructura]
            Repo[SqlDeliveryRepository]
            Roster[CourierRosterAvailabilityAdapter]
            Outbox[OutboxEventPublisher]
        end
    end

    BD[(🗄️ Esquema Entregas)]
    Fuente[👥 Fuente de turnos y capacidad]

    %% Relaciones
    Controller -->|AssignCourierCommand| UseCase
    UseCase -->|Usa| Ports
    UseCase -->|AssignCourier| Delivery
    Delivery -->|Evalúa| Availability
    Repo -.->|Implementa| Ports
    Roster -.->|Implementa| Ports
    Outbox -.->|Implementa| Ports
    Repo --> BD
    Outbox --> BD
    Roster --> Fuente
```

**Cómo leerlo:** las flechas continuas son llamadas, las punteadas son "implementa". Ninguna flecha sale del Dominio, y la Aplicación no apunta a la Infraestructura: los adaptadores apuntan hacia los puertos.
